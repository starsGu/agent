# 项目技术方案报告

## 一、技术可行性分析（约800字）

本项目面向脑机接口与 EEG 解码领域，建设集专业论文知识库、自然语言问答和任务执行于一体的智能 Agent。数据覆盖脑机接口系统、EEG 情绪识别、跨被试建模、多模态学习及 EEG-to-text 等方向。EEG 具有非侵入、时间分辨率高和设备成本相对较低等优势，相关研究持续增长；但论文同时包含采集设备、受试者、电极布局、采样率、预处理、模型、数据划分和评价指标等密集信息，不同实验协议下的结果不能简单横向比较。因此，系统需要保存正文、来源、版本和实验条件，而不能只记录摘要与最终指标。

上述数据适合采用 RAG。论文可以独立增量更新，无需重新训练大语言模型；正文经清洗、分块和索引后，系统只需向模型提供与问题最相关的证据，能够降低上下文长度和计算成本。关键词检索擅长匹配数据集名称、模型缩写、电极、频带和指标，向量检索擅长识别中英文改写及语义近似，两者融合适合兼具专业术语与自然语言意图的 EEG 查询。检索效果仍需通过证据命中率、Recall、MRR 等指标验证，尤其应评估中文问题与英文论文之间的跨语言差异。

Agent 负责理解用户目标、分析大量文本、拆解任务并整合结果。大语言模型可完成摘要、归纳、对比和问答，持久化 Memory 则使历史消息和工具结果能够跨请求、跨会话恢复。MCP 与 Tools 进一步赋予模型操作外部环境的能力：本地工具可执行数据处理和文档任务，联网工具可检索最新资料，RAG MCP 可查询私有知识库。项目已具备工具动态注入、断线移除和重连机制，并通过工作目录、超时、输出上限和程序白名单约束执行范围。

Skill 以 SKILL.md 固化复杂任务的输入要求、处理步骤和验收方法，Agent 读取后自主组合现有工具执行，无需重新训练模型。Plugin 再将同类 Skill 与 MCP 配置打包，支持独立启停和升级。现有 fetch-plugin、rag-plugin 与 projects-plugin 分别提供联网、知识库和文档成果制作能力。综合来看，本项目的数据基础、检索方案、模型能力和扩展机制均具备可行性；实施中需重点控制论文版权、版本关联、PDF 解析质量、跨语言检索效果和工具执行安全。

## 二、技术细节（约1500字）

### 1. 知识库构建

知识库按“文档读取—文本清洗—语义分块—动态切分—元数据添加—正文存储—向量更新”处理论文。系统接收 PDF、TXT 和 DOCX，先校验文件与格式，再提取正文并统一编码、换行和空白。普通文本型 PDF 可直接处理；扫描件、双栏排版、公式和图表可能出现缺失或顺序错误，因此归档阶段应检查文本质量，并按需增加 OCR、版面恢复及页眉页脚清理。

清洗后的自然段先进行相邻语义合并，默认相似度阈值为 0.72，每个语义块最多包含六段，标题、列表和表格保持结构边界。随后按长度二次切分，普通文本采用 512 字符窗口和 128 字符重叠，表格与其他结构化内容使用更小窗口。重叠用于保留边界上下文，后续可进一步改为优先在句界切分。每个最终文本块写入来源文件、原始段落和行号、顺序、类型、模型、时间等元数据，并生成稳定标识。正文保存于 corpus.db，向量保存于 vector.db；系统只为缺失记录生成向量，支持新论文增量更新。去重除文件名外，还应逐步加入 DOI、arXiv ID、规范化标题和文件哈希，并关联预印本与正式出版版本。

### 2. 混合检索与 RAG MCP

在线检索时，系统使用相同的候选文本分别计算向量语义相似度和 BM25 关键词相关度，再归一化并按 0.6 与 0.4 的权重融合，排序后返回最相关证据。默认嵌入模型为 bge-small-zh-v1.5，但 EEG 论文以英文为主，需对比英文、多语言模型和查询翻译方案。当前 SQLite 全量读取与逐条评分适合原型和中小规模知识库；数据扩大后，应将关键词检索迁移到倒排索引，将向量检索迁移到 FAISS、Qdrant、Milvus 或 pgvector 等近似最近邻方案，并可增加重排模型。

RAG 通过独立 MCP Server 接入 Agent。服务读取语料库、向量库和模型配置，在本机 8001 端口通过 Streamable HTTP 提供标准工具。归档能力负责接收合法文件路径并触发处理与向量更新，检索能力接收完整问题并默认返回五个最相关文本块。rag-plugin 登记服务名称、地址和传输方式；启用后，MCP 客户端发现工具并动态提供给模型。RAG 只返回证据，最终答案由 Agent 生成；结果为空时应明确提示，且证据需保留论文来源、版本和位置供用户核查。

### 3. Agent、Memory 与 Tools

Agent 基于 LangChain 与 LangGraph 构建，通过兼容 OpenAI 规范的接口连接所配置的大语言模型。每轮请求将用户问题、工作目录、系统提示词、历史消息和可用工具组成上下文。模型判断直接回答或生成结构化工具调用，工具结果返回后继续推理，形成“理解—规划—执行—观察—再决策”的闭环。

Memory 由 Checkpointer 按唯一 thread_id 持久化用户消息、模型消息和工具结果。相同标识可恢复历史，实现服务重启后的跨会话延续。项目默认使用 SQLite，也可切换 PostgreSQL；Web 端另存标题和更新时间。模型失败、MCP 断线或没有有效回复时，本轮新增状态会被回滚。历史过长时可通过摘要、窗口裁剪和重要事实提取控制上下文规模。

本地 Tools 以明确的名称、参数和返回结构注册；MCP 工具由已启用插件动态汇总，断线后立即移除并定时重连。run_python 在指定工作目录执行 Skill 所需的临时 Python 任务，并校验内容大小、超时和输出；tavily_search_online 用于最新公开资料检索。生产环境还需采用最小权限、隔离运行、资源配额、来源核验和操作审计。

### 4. Skill 与 Plugin

系统扫描已启用插件的 skills 目录，读取各 SKILL.md 的名称和简介。模型平时只看到简短目录，任务匹配时再通过 skill 工具加载全文，并按其中的输入检查、步骤、工具选择和验收要求执行。Skill 可引用 references、templates 和 scripts；补充资料和脚本只能在登记的 Skill 目录内读取或运行。兼容的开源 Skill 可直接纳入，但上线前必须确认许可证、依赖、路径和脚本安全。

插件采用“插件名—版本号—内容”的层次，每个版本包含插件清单、MCP 配置和 skills，也可附带脚本、参考资料与模板。fetch-plugin 配置网页抓取和图标下载服务；rag-plugin 配置知识库接口；projects-plugin 包含 docx、Markdown/HTML、PDF、PowerPoint、p5js 等 Skill，用于制作项目所需的文档、网页、演示文稿和交互内容。该结构使核心 Agent 保持稳定，业务能力能够独立组合、升级和审计。
