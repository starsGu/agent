## 目标

将 `webui/frontier` 做成一个简洁、完整的 React Agent 聊天网页。用户打开页面后，可以立即开始对话，不需要理解项目结构或进行额外配置。

## 页面效果

页面采用常见的 AI 聊天布局：

- 顶部显示产品名称 `Frontier` 和 Agent 当前状态；
- 中间区域显示完整对话；
- 底部固定消息输入框和发送按钮；
- 没有消息时显示欢迎语，引导用户开始提问。

用户消息和 Agent 消息使用不同的对齐方式与颜色，让对话关系一眼可辨。页面整体保持简洁，不保留 React Logo、教程链接或脚手架示例内容。

## 对话体验

用户输入内容后，可以点击发送按钮或按 `Enter` 发送；`Shift+Enter` 用于换行。

消息发送后：

1. 用户消息立即出现在聊天区域；
2. 页面显示 Agent 正在回复；
3. Agent 返回结果后，回复追加到用户消息下方；
4. 对话自动滚动到最新消息。

等待回复时不能重复发送。请求失败时保留当前对话，显示明确的失败提示，并允许用户重新发送失败的消息。

## 页面状态

页面需要完整处理以下状态：

- **初始状态：** 显示欢迎语和输入框；
- **正常对话：** 按时间顺序显示用户与 Agent 消息；
- **等待状态：** 显示 Agent 正在回复，并暂时禁用发送；
- **失败状态：** 显示错误和重试入口，不清空已有对话；
- **长对话：** 消息区域独立滚动，输入框始终可用。

## 视觉要求

- 使用清晰、克制的现代聊天界面；
- 正文区域在宽屏上居中，避免消息行过长；
- 消息内容支持多行文本和长文本自动换行；
- 输入框、按钮、等待和错误状态必须清楚可辨；
- 手机屏幕上不得出现横向滚动，输入和发送操作保持完整可用。

## 范围

本次只重写 React WebUI。Agent 如何实现以及服务端使用什么技术，不属于本次变更。

## 完成标准

当用户能够在电脑或手机浏览器中打开 Frontier，连续发送消息，看到 Agent 回复，并能正确处理等待和失败情况时，本次 WebUI 重写完成。
